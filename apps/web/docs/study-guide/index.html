Open the app

Engineering a useful AI co-writer

Trace a creative goal through retrieval, reliable interactions, and honest evaluation.

FunnyLLM turns a picture or a thought into complete memes, then gives the user control over the result.

Start with one decision

A cat is sitting on a laptop. The user’s intended spirit is “the groupmate who wants credit without helping.” Must the caption mention the cat?

Reveal the reasoning

No. “Put my name on it.” can connect the image’s attitude with unearned credit. The useful target is the relationship. Repeating the object can miss it. This is an authored teaching example, not a measured humor result.

Explore the example

Study the decisions in order, or jump to a mechanism from the chapter rail. You need basic web/API knowledge; the AI and database concepts are explained where they first matter.

What is implemented, and what is still unproven?

The deployed product opens on a public gallery. Funny Lab returns three image-caption options, supports targeted edits, private drafts, PNG export, and explicit sharing. Admin operations cover moderation, the image library, request traces, workflow, models, examples, and access.

The 29 October release record reports 59 user-app tests and 51 admin tests, plus live browser checks. These protect behavior and access. Human preference evaluation is still pending; no improvement in humor has been established.

All calculations and caption examples in this guide are teaching demonstrations. They make no model calls. The original Hum planning guide is preserved in the local deliverable’s archive.

Next: the creative objective

1. Turn a creative goal into a contract

Learn to separate hard constraints, intent, and optional surface details.

A caption can obey every noun in the request and still fail the user. Define success at the level of the image-caption pair: amusing, economical, and recognizably connected to the intended spirit. Code can check format and ownership. People must judge whether the joke works.

PreserveMeaning in this exampleHow to enforce it
Hard constraintsThe chosen image, a required quoted phrase, audience boundaries, and the 20-word / 200-character ceiling.Validate references and lengths in code. Reject invalid output without cutting off a punchline.
Comic intentUnearned credit, an attitude, or a social contradiction.Keep the original text and a compact interpretation. Evaluate connection in human review.
Surface details“Cat,” “laptop,” and the user’s exact sentence.Allow omission and analogy unless the user explicitly locks a phrase.

Compare three ways to miss or serve the intent

Keep the same image and spirit. Predict which part each caption preserves.

Caption approach
Put my name on it.

The caption omits the cat and laptop. The pose and the user’s context can supply the missing connection to unearned credit.

Put the objective into the prompt

The shared writer contract asks for a voice, status claim, consequence, or reversal that works with the image. Default to roughly 3 to 10 words, one comic turn, and distinct angles. Avoid scene narration, forced wordplay, an explanation after the punchline, or three paraphrases.

Write a short line that becomes funny WITH the image.
Use the spirit as direction, not wording to repeat.
The main object need not be the punchline.
Leave a connection the audience can recover.
Keep explicit locks. Return distinct complete options.

Productive ambiguity lets the audience supply a plausible bridge. An unrelated sentence merely makes the viewer invent context. Less obvious is useful only while the intended connection survives.

Check your reasoning

A five-word caption omits the entity named in the thought. What evidence would make that acceptable?

Hint

Ask whether the name was a hard lock or a soft direction.

Answer and reasoning

The image and caption must still evoke the intended target or relationship, and no explicit lock may be broken. Lexical overlap alone cannot establish success. Inspect the pair and ask a human to judge its connection.

Next: the system

2. Give each stage one job

Follow both entry paths through the implemented two-call workflow.

A bounded workflow has a fixed set of stages and a deadline. FunnyLLM uses interpretation and composition as its two generation calls. This exposes useful intermediate state without an open-ended loop of critics.

Keep intermediate outputs small and inspectable

Interpretation records the target, spirit, explicit constraints, visual anchors, possible angles, and three search views. Keep the original text alongside this abstraction: a useful summary can still erase a specific target. These fields are compact task outputs, not a reasoning transcript.

Composition sees the original input and interpretation. Picture mode also sees the image; thought mode uses trusted catalog descriptions. It chooses image and caption jointly from allowed IDs. Zod validates the structured response against a schema, so a hallucinated image ID cannot become an arbitrary URL fetch.

Study the critical path

The critical path is the sequence that determines completion time. Work done in parallel contributes its maximum duration, not the sum. In this simplified thought example, media delivery overlaps composition.

What does one more critic cost?

Hypothetical seconds. Predict the change before adding a serial critic.

Entry mode

5.3 seconds for the illustrated picture path; 2 generation calls.

1.6 interpretation + 3.5 composition + 0.2 layout = 5.3 s

Static worked thought path: 1.0 + 0.4 + max(3.5, 0.8) + 0.2 = 5.1 s; adding a critic gives 7.1 s. These values are not benchmarks.

The live generation deadline is 15 seconds. Real stage events acknowledge work; the interface calls out a wait after eight seconds and reveals complete memes. It preserves the last result on failure. Cancel stops the client request and sends an abort signal, but cannot reverse provider work already performed.

The admin’s successful-draft compute p95 is the 95th percentile among recent successful drafts. It excludes upload, browser rendering, and final save. Read it alongside failures, and measure end-to-end waiting separately.

Next: teaching data

3. Turn trusted data into usable assets

Separate source facts, derived interpretations, and delivery failures.

The teaching images and supplied descriptions are trusted for this project. There is no semantic approval queue. Data engineering still has to preserve identity, resolve assets, fill missing fields, and build compatible search representations.

Original offeringQuantity / formatUseful role
Image inventory887 rows; 886 unique external URLs; 781 marked common-use. Binary images were not bundled.Retrieve source media and preserve aliases and IDs. Common-use is metadata, not a quality gate.
Text fields740 descriptions, 209 additional-context fields, 748 recognition fields.Use descriptions directly. Backfill missing descriptions with explicit provenance.
Existing vectors477 vectors of 1,536 dimensions; model undocumented.Do not mix these with a new model, even if dimensions match. Re-embed consistently.
Captions / feedback11,516 captions on 290 images; 655 repeated image/text rows; 7,405 votes; 19 saves.Potential research material. Sparse, exposure-dependent votes are weak labels, not gold humor scores.

The implemented preparation pipeline

  1. Decode and normalize. Bound file size and pixel count, reject unsupported media, strip metadata, normalize orientation, and hash sanitized JPEG bytes.
  2. Preserve source facts. Keep provided descriptions. Store generated missing descriptions with provenance. Record unavailable media as a delivery failure.
  3. Derive possible comic roles. Store relationship labels separately. “A person behind bars” is a fact; “self-imposed confinement” is a possible use.
  4. Embed a combined search document. The implementation uses one normalized 768-dimensional Gemini embedding-001 vector per combined description/relationship record. Keep its model and version consistent.
Initial import evidence.

884 image rows decoded into 722 distinct sanitized assets. There were 885 new embeddings, 142 backfilled descriptions, and 877 rows with derived relationships. Three media failures were recorded. Embedding presence and usable image delivery are separate conditions; these counts describe the initial import, not a live dashboard.

An embedding maps text into a numeric vector whose distances can reflect meaning. Different models define different coordinate systems. Combining old and new vectors can produce meaningless comparisons even when their lengths match.

Exact image hashes remove byte duplicates; they do not establish perceptual or template-family uniqueness. The 722 initial assets ship with the app. Admin uploads use private Storage, are normalized and embedded, and enter retrieval without a redeployment. Retiring an image stops new retrieval while preserving historical draft access.

Check your reasoning

Why can an image have an embedding but still be ineligible for retrieval?

Hint

Search representation and media availability are different dependencies.

Answer and reasoning

A vector may exist while its image failed to download or decode. Returning that row would give the user a broken meme. Filter by usable media as well as compatible embedding version.

Next: retrieval

4. Retrieve a relationship, not just a noun

Understand multi-view search, rank fusion, and joint image-caption choice.

Retrieval-assisted generation supplies a model with selected external context. Here the context is an image that can carry a comic relationship. A document containing the right words is not necessarily a useful visual setup.

Change what “relevant” means

Thought: “Me organizing my to-do list instead of doing anything.” These candidate scenes are authored examples.

Retrieval strategy

Queries: to-do lists; preparation replacing action; elaborate readiness with no movement.

Candidate sceneWhy it entersPossible caption
Athlete still at the starting lineReadiness without actionPreparation is going incredibly well.
Person comfortable behind barsSelf-imposed confinementI built myself a system.
Laptop with an elaborate plannerDirect topic matchThe list has a project manager now.

Relationship channels admit images without a planner. The writer must still make the connection understandable.

Trace the shipped retrieval algorithm

  1. Generate three query views: original target, abstract relationship, and visual analogy. Embed them in one batch.
  2. For each view, get the top 20 cosine-similarity results and top 20 full-text results. Cosine compares vector directions; full-text search preserves exact words and entities. This yields six ranked lists.
  3. Combine positions using reciprocal rank fusion (RRF). Raw cosine and lexical scores have different scales; ranks give a shared basis.
  4. Take the top 40 fused candidates, then select eight distinct image families. The composer chooses three image-caption pairs jointly from that shortlist.
score(image) = Σ 1 / (60 + rank)

Sum over lists containing that image. Ranks start at 1; an absent image contributes zero. The constant 60 smooths the advantage of a single high rank. This score is not a probability of being funny.

Try a two-list fusion example

Image A is first in topic search and absent from relationship search: 1 / 61 = 0.01639. Image B is ninth in topic search. Change its relationship rank and compare.

B: 1/69 + 1/61 = 0.03089. B outranks A through evidence from two lists.

This toy uses two lists with equal weights. Production fuses six. Fusion improves candidate coverage; it does not establish joke quality.

The best literal image may leave nothing for the caption to add. Joint selection lets a more distant image provide the contradiction and a short caption complete it. Reliable descriptions avoid a fresh vision call per library image. Validate selected IDs against the saved shortlist.

When would more retrieval machinery be justified?

If useful images appear in the pool but remain too low, test a reranker. If descriptions omit crucial expressions or text, test thumbnails in the existing composition call. If exact search becomes slow as the catalog grows, benchmark an approximate nearest-neighbor index. Each addition needs measured benefit and a latency budget.

Embedding fine-tuning needs thought-image judgments and hard negatives: images with the right topic but wrong relationship. Writer fine-tuning needs diverse accepted/rejected pairs and edit outcomes. The historical vote export does not reliably supply either dataset.

Check your reasoning

If the topic match is accurate but every caption merely describes the image, where do you investigate first?

Hint

Inspect the search representation and alternatives already in the pool.

Answer and reasoning

Check whether the relationship and analogy views introduced useful visual tensions. Then compare joint composition with captioning only the top literal images. A longer prompt or another critic may not address the retrieval failure.

5. Let users steer without losing work

Connect edit invariants, concurrency, publication, and moderation.

An invariant is a property an operation must preserve. A targeted edit should change the requested dimension while keeping the useful parts of the joke. Different angle needs a looser contract than Shorter.

ActionPreserveChange / guard
Shorter / LongerImage, target, and chosen comic turn.Word count must decrease / increase. Every result stays within 20 words and 200 characters. Reject an invalid edit and keep the old result.
Less / More obvious; Less / More meanImage and intended comic connection.Implication or tone. These are model-directed changes, not calibrated numerical sliders. Meaner retains safety boundaries.
Different angleOriginal spirit and explicit locks.The premise and wording can change. Locking the old premise would defeat the action.
Swap imageChosen intent and attitude.In thought mode, select another image from the saved shortlist and adapt the wording. Never silently replace a personal upload.
Manual edit / Undo / ExportUser control and an actual selected revision.Manual text still respects render bounds. Undo restores stored state. PNG export resolves authorized media.

What happens when requests race?

Idempotency makes a repeated request ID return the same operation instead of generating twice. A content fingerprint detects reuse with a different payload. Optimistic revision checks only commit against the version the user edited.

Current draft: revision 7
Request A starts from 7. Request B also starts from 7.
A commits revision 8.
B finishes late: expected 7 no longer matches current 8.
Reject B's stale commit; keep revision 8 visible.

Model and active examples are frozen when a draft starts. An admin model change applies to new drafts, so an existing editing session does not silently switch its creative runtime.

A private draft is not a public post

Publishing copies a selected revision’s image and caption into an immutable snapshot. The public alias is intentional; the account email, private brief, and traces stay private. A unique session/revision/option key prevents duplicate publication on retries.

Next: evaluation

6. Separate reliability from humor quality

Design a controlled comparison with the right unit and honest uncertainty.

Automated tests establish that outputs respect constraints, references are authorized, and failures preserve state. They cannot establish that a caption is funny. The primary creative evaluation should use human judgments of complete image-caption sets.

QuestionEvidence to collectMisleading substitute
Is it worth using?Blinded preference with win, tie, and neither; at least one keepable option.The model’s own funniness score.
Does it connect?A separate pass revealing the user’s spirit and rating recognizable intent.Required overlap with every noun.
Does co-writing help?Time and edits to first keep; whether the requested edit preserves the right invariant.Counting every regeneration as success.
Is the app usable?End-to-end p50/p95, failures, abandonments, and cost per accepted task.Only successful model-compute latency.

Change one cause at a time

An ablation removes or replaces one component to estimate its contribution. The implemented development harness tests two separate hypotheses:

  1. Picture mode: direct composition versus interpretation followed by composition, with the same creative rules, model, output limits, and three options.
  2. Thought mode: literal retrieval versus original/relationship/analogy retrieval. Reuse the same interpreted intent and keep the writer, catalog, model, shortlist size, and output count fixed.

The old two-caption comparison product is a separate end-to-end reference. Its different prompts, output count, and interactions prevent it from isolating the effect of retrieval alone.

Do not inflate the sample

One requestShared intent + shortlist + model callThree related captionsOne task-level preference outcome

Three captions from one request share causes; treating them as independent trials makes uncertainty look too small. Aggregate raters within the task, then use a task-cluster bootstrap: resample whole tasks, preserving the related observations. Repeated users and image families need additional design or statistical care.

Hold out answers, not searchable knowledge

Thought mode is supposed to find images already in its catalog. Their trusted descriptions can be indexed before testing. Hold out test thoughts, preferred captions, and relevance judgments from tuning. For a separate claim about unseen pictures, hold out image/template families. Near-duplicate prompts should stay in the same split.

A practical next evaluation
  1. Observe 5 to 8 users using both modes to find interaction problems; do not treat this as a population estimate.
  2. Prepare roughly 30 to 50 fresh tasks per mode and multiple independent reviewers. These are pilot planning ranges, not a power calculation.
  3. Randomize execution and presentation order. Judge humor before revealing the spirit, then judge connection. Retain failed arms.
  4. Report raw wins, ties, neither, coverage, failure rate, and task-level uncertainty. Use useful-hit@8 for judged retrieval pools; incomplete labels cannot establish exhaustive recall.
  5. Set the practical gain and acceptable latency/connection losses before a confirmatory run. Keep the simpler system if added complexity is unsupported.

Cost per accepted task should include spend on failures and abandoned work. For example, $4.80 across 120 tasks with 80 accepted memes gives $0.06 per accepted task. This arithmetic is illustrative. Report preprocessing separately.

Current evidence boundary.

The six development fixtures include four thoughts and two variants of the same picture. They exercise the harness and expose failure cases; they are not a held-out humor study. Better captions remain a hypothesis to test.

Admin navigation follows the operator’s job

Overview answers whether the gallery and writer are healthy. Content handles reports and removal. Image library manages usable retrieval assets. Activity explains individual requests. Workflow exposes source-controlled steps and validated model selection. Examples manages up to three active few-shot references. People & access shows users and authorized admins.

A few-shot example is an input/output demonstration supplied in the prompt. It can guide style, but can also anchor phrasing and cause copying. Active examples and the model are snapshotted per draft. There is one Gemini adapter; a registry entry does not create a working adapter for another provider.

Traces are private records of bounded prompts, parsed responses, timings, usage, model, and workflow version. They exclude secrets and image bytes; original text can still be sensitive. Lists omit large trace bodies and details require admin access. External Langfuse/OpenTelemetry integration and automated retention cleanup are future options.

Next: interview practice

8. Explain the decisions from memory

Attempt these aloud before opening the hints. The transferable skills are objective design, representation, retrieval, workflow budgets, evaluation boundaries, and interaction contracts. Tool names alone do not explain the project.

1. Translate a creative goal

Why can exact instruction adherence be the wrong main metric here?

Hint

Name what stays hard and what becomes soft.

Answer criteria

Explicit constraints still matter. The spirit is a direction; lexical coverage and literal object naming are free to change. Evaluate humor first among valid, recognizably connected pairs. This is a domain-specific objective, not permission to ignore user requirements.

2. Defend the representation

Why keep the original thought alongside an abstraction?

Hint

What information can a useful summary accidentally remove?

Answer criteria

Abstraction finds shared relationships across different objects, but can erase the target or attitude. Keeping the original lets retrieval retain a direct channel and lets the writer recover intent. Test for concept drift rather than assuming the planner is correct.

3. Explain creative retrieval

How is retrieving a meme image different from answering a factual question with RAG?

Hint

What counts as useful evidence or context?

Answer criteria

The goal is an image that supports a comic relationship, not a document that contains the answer. Topic similarity is only one signal. The final quality unit is image plus caption; optimize and evaluate that pair.

4. Avoid unnecessary data work

The owner trusts all images and descriptions. What work can you remove, and what remains?

Hint

Separate source truth from system representation.

Answer criteria

Remove semantic re-qualification and mandatory per-image human approval. Keep missing-field handling, IDs, asset delivery, duplicate grouping, versioned embeddings, and evaluation of our derived retrieval features. Historical caption votes remain a separate weak signal.

5. Control latency

Interpretation takes 1.0 s, search 0.4 s, composition 3.5 s, media fetch 0.8 s in parallel with composition, and layout 0.2 s. What does a serial 2.0 s critic do?

Hint

Compute the critical path; do not add parallel work twice.

Answer criteria

Base path is 1.0 + 0.4 + max(3.5, 0.8) + 0.2 = 5.1 s. The critic raises it to 7.1 s. These illustrative times say nothing about real p95. Measure whether the extra quality is worth the added wait and cost.

6. Recognize leakage correctly

Why can the test’s relevant image be in the thought-mode catalog?

Hint

Catalog knowledge and training answers serve different roles.

Answer criteria

The product searches a known catalog, so indexing its descriptions is intended. Hold out test queries, preference labels, and accepted captions from tuning. Use separate image-family holdouts for claims about new visual inputs or caption-example generalization.

7. Design controlled creativity

Why should “Shorter,” “Different angle,” and “Swap image” have different invariants?

Hint

Which part is the user explicitly trying to change?

Answer criteria

Shorter preserves the comic turn; new angle preserves only spirit and hard constraints; swap preserves intent while adapting wording to a new visual. A single over-strict preservation rule would prevent meaningful creative changes.

8. Tell an honest interview story

What would you say if the simple baseline beats your more complex workflow?

Hint

A useful engineering conclusion can be a removal.

Answer criteria

Explain the hypothesis, controlled comparison, observed tradeoff, and decision to ship the simpler path. Preserve the failed experiment as evidence of disciplined evaluation. Before measuring, describe this work as design or implementation, not a proven humor improvement.

A later recall pass

Draw both entry paths from memory. Explain why the main object need not appear in the caption. Derive the thought-mode latency equation. Then design a two-condition experiment that changes only the retrieval query representation.

Mark what you can demonstrate

Session-only self-checks. They are not saved or treated as proof of mastery.
