# App audit — October 22, 2026

## Results and configuration navigation

The default overview scores only the currently active pair. Historical results are an explicit separate view. Every leaderboard and head-to-head name links to its configuration. Prompt Lab exposes retired revisions and original legacy prompt templates; reuse creates a new editable revision without reassigning historical votes. New-revision feedback explains activation and links to the saved revision. Reversing an activation pair now combines votes before fitting a single prior; displayed score ties share a rank. Head-to-head totals combine both activation orders and show vote counts.

## Automated verification

45 admin tests and 36 user-app tests passed, including the following integration and regression coverage. Both apps passed full ESLint and production builds with TypeScript checks.

- Access: anonymous and member RPC denial, Google provider restriction, no self-promotion, fresh database role lookup, private-table denial, safe login return destinations.
- Data: prompt field bounds and model validation, separate immutable revisions, invalid/retired/duplicate active selections, active retirement rejection, captured configuration provenance during activation changes, image/caption/vote cascade, deletion confirmation.
- Ratings and runs: vote-before-ready denial, repeat votes retain the first choice, invalid choices, individual vote privacy, poll/method disclosure gated by saved vote, foreign pending-run privacy, wrong writer keys and attempt tokens, expired-run recovery, published-pair immutability.
- Generation: exact saved prompt/system/model/temperature transport, independent concurrent requests, cancellation and settlement on sibling failure, bounded duplicate retry, malformed/incomplete provider output, invalid configurations, no credential-bearing provider bodies in user-facing errors.
- Images/profiles: unsupported, empty, oversized, disguised, truncated and high-resolution source files, bounded resize/transport, metadata removal, required profile names.
- Ranking: order independence, reversed activation orders, equal scores, disconnected groups, zero votes, all wins and Wilson interval bounds.

## Browser checks before release

Chrome desktop: current vs historical results, historical-result deep links, expanded original instructions and reusable prompt, existing saved-vote display, own failed-run recovery screen, duplicate active pair rejected without changing the live selection.

Chrome at an actual 375px viewport: overview, media, people/votes, Prompt Lab, user feed, upload, profile and run history. No page overflow or unlabeled form controls in the tested forms. The final fresh user-app tab had no captured console errors. Local testing caught stale assets after rebuilding a running server; final checks used restarted servers and a fresh tab. The error boundary now offers a full reload for stale deployment chunks.

New empty-page recovery links and progress auto-checking were also reviewed in code. Auto-checking handles session expiry, deleted runs, finished/failed runs, lease expiry, unmount cancellation and transient network errors. A real member account was not signed into in the browser; member denial was exercised in an isolated Postgres fixture. These checks are broad regression coverage, not an exhaustive guarantee for every browser, provider outage or concurrent workload.

## Latency measurement

The same synthetic chair image, same model (gemini-3.1-flash-lite), and same two test prompts were used against the previous serial generator and the revised concurrent generator. No database records or votes were created by this probe.

- Five controlled runs with 40ms mocked provider latency per call: serial median 124ms; concurrent median 41ms.
- One live provider probe per version: serial 4336ms; concurrent 1211ms. Both made three calls. The concurrent individual calls took 1110ms, 1145ms and 1209ms.

This is a measured single live sample, not a statistical speedup guarantee. Real upload latency also includes image handling, storage, auth and database calls. All four model IDs offered by Prompt Lab were listed by the configured Gemini project. Per-render admin auth checks are deduplicated with React cache; database permission checks remain fresh per request and mutation.
