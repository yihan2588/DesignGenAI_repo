## Faults reproduced

The earlier pipeline asserted an ambiguous object's identity and an unseen maintenance task. The judge could accept the same guessed identity even after scene extraction stopped asserting it. Separately, source selection admitted thematic matches while all candidates cited no source. Demonstration exposure alone made the old readiness check look retrieval-backed.

## Implemented contracts

- Scene extraction describes ambiguous objects by visible features and records uncertain identity/function/task separately. The existing image-conditioned conflict call audits the draft, returning `verified_scene` and `rejected_visual_claims`. Only audited observations and conflicts enter creative stages. Rejected draft claims remain in the checkpoint, outside later prompts; uncertainties are excluded from evidence anchors.
- A grade-2 source needs a source-to-target transfer plan, verified detail IDs, and original-source lexical prerequisites for wordplay. A source annotated `wordplay_only` cannot bypass that constraint by labeling its plan relational. This conservative policy can reject a useful source with a wrong annotation; that requires an annotation correction, not a runtime bypass.
- The writer records exact caption spans and adaptations for every claimed source. The judge receives the original demonstration jokes, reads each source claim independently, and checks whether the distinctive relation or wordplay actually survives. Shared topics, nouns and generic styles are insufficient.
- The judge also audits entity/action/task claims with an explicit `literal` or `analogy` classification. The deterministic filter verifies that every listed span occurs in the caption and cites one of its real detail IDs. Literal phrases must occur in those audited observations. A generic circular-object detail cannot substantiate a specific device name, even if the judge's acceptance boolean is true. Clearly figurative phrases instead require a model-judged visible premise. An intermediate stricter implementation wrongly treated toy metaphors as literal identities; it was corrected and retained in the private report. Literal paraphrases can still fail the conservative exact-phrase check, and the model can misclassify a claim.
- In `balanced_rerank`, a retained caption must have at least one verified source transfer, and every claimed source must pass. `retrieval_evidence_ids` now records verified transfers among retained captions, `selected_caption_source_ids` records the winner's sources, and `admitted_source_ids` separately records exposure. If no candidate passes, `guided=null`; a grounded `association_only` diagnostic may remain. It cannot publish a RAG pair.

Normal execution still uses eight model calls, with ten persisted attempts and one schema repair. Checkpoint names are unchanged; no SQL migration is required. New implementation/prompt fingerprints prevent old checkpoints being replayed under the new contract. The independent baseline prompt and provider/model are unchanged; fresh baseline outputs are still stochastic.

## Provider compatibility

The expanded judge schema initially received HTTP 400 rejections. A bounded replay confirmed the failure, and a one-request qualification succeeded after simplifying the wire grammar. The provider schema retains types, references, required fields and closed objects, while removing string/array size/pattern constraints from the wire. Full Pydantic bounds and all reference, grounding and transfer checks remain mandatory locally; payload/output-token limits remain enforced. This follows the [Gemini structured-output documentation](https://ai.google.dev/gemini-api/docs/structured-output), which documents a schema subset, possible rejection of large/deep schemas, and application-side validation. The exact server-side cause of the generic invalid-argument response is not exposed; complexity is an inference supported by the successful simplified request.

All failed attempts remain in the run history and budget ledger. Calls without provider usage remain conservatively reserved rather than assumed free. The schema qualification is a diagnostic, not a completed end-to-end pipeline run.
